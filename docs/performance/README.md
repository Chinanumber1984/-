# W10–11 绩效前置

用户于 2026-10-27 明确批准开始 W10–11。范围 FR-PER-101~105/201~203、FR-POR-305。此前本机数据库、密钥和账号必须保留。

契约：内部 `/srm/v1/performance`，门户 `/client/c/srm/v1/performance`，统一身份由服务端取得。GET `/templates`、`/scores`、`/scores/{id}`、`/suppliers/{id}/summary?endPeriod=YYYY-MM&months=12`、`/export`；POST `/templates`、`/imports`、`/calculate`、`/scores/{id}/appeals`、`/appeals/{id}/review`。分页与导出使用相同组织/SELF/供应商隔离。错误码 400 输入错误、403 角色拒绝、404 不存在或越权、409 版本/幂等冲突。

评分模板为全公司单一版本序列，不接受品类或组织权重。默认交付/质量/成本/服务=30/35/20/15；总和必须100。等级阈值默认90/80/70/60（战略/优选/合格/观察；低于60为淘汰建议），允许授权SQE或采购经理发布新版本，按生效月份选取。历史结果记录模板、输入版本和分项贡献快照；重算同输入不新增版本。

本阶段仅导入显式标记 HISTORICAL 或 SANDBOX 的四项0~100分数据和来源引用，不冒称ERP/MES/QMS联调。每批最多500行，同一请求键与同一内容幂等；冲突返回409。新输入版本不覆盖旧证据。每月上海时间1日03:00计算上月已导入数据，也支持授权人员手工计算。

门户仅ADMIN/QUOTE/QUALITY/FINANCE可看本供应商绩效和申诉；SHIP无此权限。SQE复核必须携带待审评分版本，批准修正保留新输入和评分版本，驳回不改分。待申诉期间普通导入/重算不得覆盖审查依据。

绩效等级可联动合格供应商TIER，永不直接改变准入STATUS；低于观察阈值只给淘汰建议并把等级置观察，淘汰仍须走已有审批。更早月份重算不能覆盖最新月份等级。

近12月接口按实际有效月份平均，返回月数、缺月和完整性提示；无历史各分数返回null，requiresApprovedException=true，不伪造满分/零分，不开放客户端绕过参数。后续定点阶段必须处理获批例外；实际ERP/QMS接入和性能两小时指标仍待P7/专项验证。

迁移 V6 仅新增绩效表，保留旧表与数据。现有验收包升级前备份数据库与应用文件；不覆盖runtime。本机实测结果见下文与本目录JSON证据。

## 本机使用与升级

访问 **http://localhost:18080/**，用原账号登录后选择左侧“绩效管理”。原登录信息仍位于 `artifacts/SRM-local-review/runtime/登录账号.txt`；不在文档中复制密码。

1. SQE/采购经理查看全司统一模板，可发布同生效月份的新修订或未来最多12个月的模板；已有模板行与已计算快照均保留。
2. “录入或导入评分”选择供应商、月份、历史/沙箱来源和可追溯凭据编号，填写四项分数；也可下载UTF-8 CSV示例并上传批量来源。导入与计算分步提交，若计算被申诉阻止，已导入来源仍保留，可处理后重算，不必重复制造导入记录。
3. 列表按月份、品类、绩效等级筛选，查看明细中的输入版本、模板版本、四项贡献与历史评分，导出同范围Excel。
4. 近3/6/12/24/36个月趋势按实际有效月份计算并显示缺月。定点消费默认取近12个月；无历史分数为null且必须另走获批例外，不能用趋势窗口绕过后续定点规则。
5. 门户中ADMIN/QUOTE/QUALITY/FINANCE只可看本供应商并提交申诉；SQE独立账号复核。复核期间不能覆盖该月来源，批准修正产生新版本，驳回保留原分数。
6. 最新月份等级可联动合格供应商TIER；进行中的生命周期审批暂缓联动，审批结束后同输入重算可补做等级联动而不制造新评分版本。淘汰建议需在已有生命周期工作台单独申请审批。

本机新功能需要自行录入有依据的历史数据；没有向用户原组织填充模拟评分。自动化测试使用单独命名的组织和测试供应商，凭证仅保存在被Git忽略的 `.runtime/performance/fixture.json`，测试数据保留供复核。

已有实例保留runtime和数据卷升级：

```bash
SRM_REVIEW_OUTPUT="$PWD/artifacts/SRM-next-review" bash scripts/build-local-review.sh
bash scripts/upgrade-local-review.sh "$PWD/artifacts/SRM-next-review"
```

构建目录必须是新的目录，脚本拒绝覆盖已存在包。升级会备份数据库、应用和原凭证到 `.runtime/upgrades/`，校验迁移checksum后只增加V6绩效表，保留原数据库和附件卷。V6是加法迁移，应用回退保留新增表；不要回滚删除含业务数据的表。源码开发环境通过Flyway执行V6，验收包使用独立checksum账本支持重复升级。
