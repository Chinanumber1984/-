# SRM 开发实施方案 v1.0

编制日期：2026-10-26。依据当前仓库、架构方案 v1.1、FRD v1.0、PRD 定稿。本文为研发排期基线，未将方案建议自动视为用户批准，也不表示所列功能已经实现。

当前进展以 [W3–6交付](workspace/README.md)、[W7–9首版交付](lifecycle/README.md) 和 backlog.csv 为准；下文起点描述保留制定排期时的状态。

## 1. 当前起点与交付目标

当前是可运行的开发骨架：Snowy 源码、七组插件/API 模块、三个核心实体和表、只读供应商分页、前端页面、两节点 BPMN 模板。已有四项测试通过和构建/启动记录；供应商新增、审批业务回写、SRM 门户与外部集成尚未完成。

FRD 实际有 114 个唯一 L3：CORE 28、SRC 19、COL 18、PER 20、POR 14、FLOW 9、INT 6。原文合计 122 不作为交付计数。以 docs/backlog.csv 为编号基线，以 PRD 特异 AC 和 G1–G6 为验收要求；一个编号可以分阶段实现，但只在全部 AC 满足后关闭。

首个业务版本交付：注册/内部录入→档案/资质/联系人→SQE 审核→经理审批→合格→关键资料变更/冻结/解冻/淘汰，配套门户自助、组织隔离、审计和待办。完整版本再交付绩效、询比价/竞价、采购协同、质量风险与真实系统集成。

## 2. 技术基线

- 基于当前 Snowy v3.7.0 来源提交继续开发；Maven 内部坐标 3.0.0 不代表业务版本。
- Java 17、现有 Spring Boot 3、MyBatis-Plus、Sa-Token；Vue3、AntDV4、Vite5、Pinia，内部和门户同一个前端工程。
- Flowable 7.1.0 承担审批；组织与供应商数据隔离由业务服务统一实施，不能仅凭候选角色组实现。
- 首版以已验证的 MySQL8 为唯一交付数据库，Redis7 为缓存。PostgreSQL16 作为独立迁移任务，尚未实现双库兼容；若必须以 PG 为生产库，应在 P1 完成切换、迁移和全量验证后重估排期。
- MinIO 复用 Snowy 文件服务；对象路径、附件元数据与下载授权均关联组织/供应商。新增 Flyway 版本迁移，生产升级禁用自动建表；Flowable DDL 使用受控升级流程。
- 单体模块化部署，保持七组插件及 API 边界。首版不引入微服务拆分。可靠集成先采用事务 outbox/inbox 加持久化重试任务；只有既有基础设施与吞吐要求明确时才引入 MQ。

## 3. 开工前必须解决的口径

以下为建议基线，在 P1 评审并落实为规则及测试；存在分歧时标记影响项，不阻塞其他开发。

| 事项 | 建议基线与影响 |
| --- | --- |
| SQE/SQM 单价权限 | 统一业务角色编码 SQE。按字段授权策略配置“查看单价”，未授权默认隐藏；业务负责人确定哪些用户具备此权限。不能沿用文档中互相冲突的默认展示规则。 |
| 注册和准入 | 注册先建潜在档案，资料不完整允许暂存，证书完备后提交审批；“注册自动转准入”解释为自动建立申请入口，不跳过资料门槛。 |
| 信用代码唯一 | 供应商编码全局唯一，信用代码按 org 唯一；信用代码规范化后使用受密钥保护的确定性检索指纹做唯一约束，原值 SM4 加密。密文不能直接用于可靠唯一性校验。 |
| 有效期与时区 | 业务时区 Asia/Shanghai，证书 valid_to 当天有效、次日过期；时间戳统一保存并明确 API 时区。 |
| 冻结影响 | 禁止新增 RFQ 邀请、竞价参与和 PO；存量订单的发货/收货/对账处理策略由采购与财务在 P1 确定，不能一刀切造成无法结算。 |
| 缺少绩效历史 | 支持导入可追溯历史；不足12个月使用实际有效期并显式提示。完全无历史时不得伪造满分或零分，定点须走获批的例外规则。 |
| 比价公式 | 明确到厂价税/运费/币种与汇率口径、成本归一化公式及异常值规则；权重全公司统一30/35/20/15，保存计算版本和输入快照。 |
| 防狙击 | 按 PRD 使用合法出价命中最后N分钟后 endTime += N；明确是否封顶。无封顶时必须展示可持续延期的规则。无效/重复请求不触发延期。 |
| 竞价地址与保密 | 统一提交地址为 /app/bid/submit。公共广播仅匿名公共信息；yourPrice/yourRank 通过用户私有通道发送，不能放进共享 topic。 |
| 风险与冻结 | 风险高等级仅生成冻结建议待办，业务状态由审批结果改变；不直接更新为冻结。 |
| 修正次数与等级 | 补正上限默认3但计数事件需明确；等级阈值、首次准入等级和绩效降级对应动作均配置并版本化。 |
| 外部系统范围 | 基准排期包含一种 ERP、一种 QMS、一种 MES、一个财务共享和一种消息通道。多厂商多版本适配单独估算；OA为选配，不替代已锁定的Flowable。 |

## 4. 架构实施要求

### 4.1 数据与接口

- 所有业务聚合明确归属 org_id；子表继承父聚合归属并通过受权限约束的关联查询访问。与供应商有关的数据同时关联 supplier_id。
- 内部支持本人/本机构/本机构及下级/全部等获授权范围；本人范围必须过滤创建人，不能把它当成本机构。门户身份包含 account_id、contact_id、supplier_id、roles，由服务器会话产生。
- ID 沿用 Snowy 字符串，金额使用 BigDecimal/DECIMAL；业务 JSON 结构提供校验和版本号，不接受任意无约束字段。
- 实体不直接充当请求或响应。输入 DTO 白名单、防批量赋值；响应 DTO 实施字段权限与脱敏；列表、详情、导出、附件和 WebSocket 使用同样的隔离规则。
- 扩展 PRD 的最简实体：审批关联/业务事件、变更版本、报价轮次及行明细、竞价场次/邀请/出价、订单/ASN/收货行、对账双方确认、8D步骤/附件、绩效输入快照、集成重试。PRD 的19实体统计不是最终表数量。
- 先发布 OpenAPI/错误码/权限码和迁移 SQL，再做前后端实现。新增唯一约束、状态检查、版本控制和必要索引；禁止通用 edit 接口接受 status/orgId 等受保护字段。

### 4.2 审批与审计

- 首个流程实现通过/驳回/退回补正/重提，之后复用至关键资料变更、冻结/解冻/淘汰、定点、PPAP/SCAR。
- candidateGroups 只是找人条件；领取、查看、同意、驳回、转办、加签均验证组织、角色与任务归属。
- 默认同一数据库事务内完成审批及业务状态回写；使用业务键和事件唯一键防重复，失败回滚。跨系统通知使用提交后的 outbox 重试；补偿事件可见、可重放，不吞异常。
- 普通编辑不得改变生命周期；终态淘汰阻止新业务。关键字段变更在审批通过前保留旧有效值。
- @CommonLog 仅作为框架接入口，增加业务事件和签名完整性验证；不得记录明文银行账号、手机号、单价或密钥。留存五年、备份和归档需要独立存储方案与验证。

### 4.3 竞价与可靠集成

- 客户端出价使用请求唯一键；服务器验证邀请、合格状态、角色、时效、金额精度和最小降幅。金额换算为受范围限制的整数最小单位，避免浮点比较。
- MySQL 保存可恢复的权威出价记录与场次版本；Redis承担原子竞争控制/缓存。Lua成功不等于业务成功：完成数据库持久化后才确认出价并广播。
- 对 Redis成功而数据库失败、数据库提交而响应丢失、锁超时和实例重启，设计场次暂停/重建、幂等查询和补偿路径；在故障注入测试完成前不开放真实竞价。
- 每场竞价采用可证明的串行决策机制和场次版本检查，封盘、延期、最低价与排名使用同一有效版本。Redis故障暂停出价；恢复后按已提交记录重建。
- ERP/MES/QMS/财务使用业务键+源系统+事件版本幂等；outbox/inbox重试有退避、最大次数和人工处理。请求日志脱敏，保留回执和对账结果。
- 备份恢复和审批/竞价/集成的历史不可通过 Redis 数据单独恢复。

## 5. 排期基线与里程碑

估算前提：2名后端、2名前端、1名测试，产品/采购/SQE/财务代表参与每周验收，另有兼职运维；接口资料和测试环境按时到位。W1代表正式开工第一周，不是承诺日历日期。基准24周，跨系统等待和真实试运行变化另留2–4周风险空间；这是团队容量估算，不是AI自动开发的完成承诺，也不是功能点平均分配。

| 阶段 | 周次 | 开发范围 | 退出条件 |
| --- | --- | --- | --- |
| P1 基础与评审 | W1–2 | 需求口径、API/表设计、Flyway、RBAC/组织/字段授权、密钥/附件、CI、集成契约与沙箱 | 两组织两供应商隔离测试基线成立；迁移可在空库/已有开发库执行；规则决策有负责人 |
| P2 主数据与门户基础 | W3–6 | CORE-1xx/2xx/3xx、POR-201~203/401~402；档案、证书版本/预警、联系人多角色和账号绑定 | 新增编辑校验与加密、证书续期留旧版、最后ADMIN保护、停用账号禁登录；跨供应商读写/下载/导出被拒绝 |
| P3 准入与生命周期 | W7–9 | CORE-4xx/5xx/6xx、FLOW全部、POR-101~103首版、INT-105首个消息通道 | 注册→补资料→两级审批→合格及驳回/补正/重提全部跑通；变更/冻结/解冻/淘汰可审计；审批回写失败可恢复 |
| P4 绩效前置 | W10–11 | PER-101~105/201~203、POR-305；评分模板、历史导入、计算/分级/申诉 | 分项数据可追溯，月度重算幂等，权重统一，供定点调用的12个月绩效接口及无历史策略可用 |
| P5 寻源与竞价 | W12–15 | SRC全部、POR-301~302；RFQ、多轮报价、答疑、比价、实时竞价、定点审批 | 50受邀方场景、并发出价/重试/延期封盘/断线恢复/匿名隔离通过；定点真实引用绩效和风险摘要 |
| P6 采购协同 | W16–19 | COL全部、POR-303~304、INT-101/102/104；ERP订单、ASN/收货、对账、发票/回执 | 一家真实ERP及财务测试环境端到端通过，重复/乱序/失败重试不重复入账；双方确认与金额容差符合规则 |
| P7 质量风险与集成闭环 | W20–22 | PER-3xx/4xx/5xx、POR-306、INT-103/106，补齐消息与门户聚合 | PPAP/8D/质量扣分闭环，风险生成冻结建议；所有接口监控/重试/补偿可查；绩效使用真实ERP/QMS数据复验 |
| P8 总体验收与试点 | W23–24 | 全114编号验收回归、性能/权限/故障恢复、迁移演练、用户培训及试点 | 无遗留阻断缺陷，备份恢复演练成功，业务负责人签收；具备生产部署条件 |

P3结束形成首个可业务验收版本。P4使用明确标识来源的历史/沙箱数据，真实ERP/QMS接入后必须在P7重验，不能以模拟数据作为正式联调验收。P5若尚无完整风险模块，先交付稳定的内部风险摘要契约和人工风险登记；完整风险联动在P7验收，不能默认“无风险”。

P1即向外部系统索要字段字典、示例报文、认证方式、回调契约和沙箱，以便P6/P7到来前准备好。接口模拟用于研发并行，不代替真实联调。

等保三级测评和麒麟/统信/TongWeb等指定信创适配单独立项排期；本表包含安全功能实现与内部验证，不承诺外部认证机构在W24前出具结论。

## 7. 测试与关闭标准

每项功能交付必须包含：需求编号及全部AC、DTO/OpenAPI和错误码、迁移/回滚或向前修复说明、服务端权限、对应前端交互、正向/异常/越权测试、审计与必要监控证据。构建通过不能代替业务验收。

| 层次 | 关键验证 |
| --- | --- |
| 规则单测 | 日期边界、状态迁移、金额精度、权重/等级、补正次数 |
| MySQL集成 | 唯一性并发、事务回滚、迁移升级、逻辑删除与历史；H2测试保留但不替代MySQL验证 |
| 身份权限 | 两org、两supplier、多联系人多角色；覆盖列表/详情/编辑/导出/附件/审批/WS订阅与发送 |
| 审批 | 通过/驳回/补正/转办/加签/超时，重复完成与回写失败，越组织处理被拒绝 |
| 竞价 | 并发同价/降幅、幂等重试、截止边界/延时、匿名信息、Redis/DB故障、重启与恢复 |
| 集成 | 重复、乱序、超时、回执丢失、重试耗尽和人工补偿，真实沙箱对账 |
| 性能 | 万级供应商列表P95<1s；最多50受邀方竞价端到端广播延迟<500ms；月度计算≤2h。测试前固定环境配置、并发模型和统计口径 |
| 运维 | 备份恢复、发布回退/数据库向前修复、日志脱敏、告警到达；可用性/SLA按明确观测窗口统计 |

114个编号全部逐项验收后才可称“全功能交付”。门户复用项同样必须验证独立身份与权限。流程模板、空模块、未接真实数据的页面都不能作为功能完成证据。

## 8. 交付管理

每周交付一个可演示、可回归的小版本；每个里程碑用业务样例验收。需求以FR编号关联代码变更、测试、缺陷和发布记录。docs/development-workpackages.csv记录阶段分配，docs/backlog.csv保留实际完成状态，两者不能互相替代。

生产部署前单独完成运行手册、密钥注入、数据库迁移、告警、备份恢复和回退演练。当前开发环境的默认配置、样例账号及自动建表不能直接用于生产。
