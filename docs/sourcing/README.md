## 实施契约

内部 `/srm/v1/sourcing`，门户 `/client/c/srm/v1/sourcing`。RFQ、邀请、附件、报价、答疑、竞价和定点均在服务端核验组织、SELF范围及绑定供应商；门户仅ADMIN/QUOTE可访问。内部SRC-SPE/CAT-MGR可维护寻源，SQE只读。单价需独立 `/srm/fields/unit-price` 权限，默认隐藏；报价本人始终可见本供应商报价。实际报价和起始价/降幅在MySQL中SM4加密。

到厂价口径：本RFQ统一币种，报价单价含税，另列运费，总价=各行数量×含税单价（每行保留2位）之和+运费。跨币种报价不接受，不进行隐式汇率换算。成本分=最低到厂价/本方到厂价×100。综合分采用发布时全司统一权重快照和近12月实际有效绩效的交付/质量/服务均值；保存公式版本、报价轮次、绩效月份/版本、风险及权重输入，保证复算可追溯。无绩效历史不填造零分/满分，定点须经理明确批准有原因的例外。

RFQ草稿可编辑，未发布草稿即使撤回也不会出现在门户列表或通知中；发布后物料和邀请名单不变；延期和撤回有独立命令与版本校验。撤回要求没有报价或竞价出价。仅同组织、同品类的合格供应商可邀请，发布、报价、出价、定点审批和发布时重新验证合格状态。规格附件保存到私有存储，仅授权内部人员和受邀方下载。报价按供应商记录不可变轮次，公开答疑仅向受邀方可见，私聊仅双方可见。

竞价按整份RFQ的含税到厂总价出价；以分为最小单位，最大9万亿分，避免Lua浮点整数溢出。每次有效出价必须至少降低已知最低价一个最小降幅。服务器对每场RFQ持MySQL行锁，检查版本并持久化出价与签名审计后才确认；Redis Lua原子核验当前检查点。缓存缺失/故障/版本不一致暂停新增出价，按数据库已提交记录恢复。相同请求键重试返回原收据且不再次延期；不同内容重用同键被拒绝。最后N分钟合法出价触发endTime += N分钟，默认5分钟，允许连续延期且不自动封顶，界面明确展示。封盘和出价共用同一版本和锁，有效最低价产生候选，无报价流标。

STOMP地址 `/api/srm-sourcing-ws`，提交路径固定 `/app/bid/submit`。连接使用认证HTTP签发的30秒单次票据，不在URL放登录令牌；订阅仅允许本连接的 `/user/queue/sourcing-state` 和 `/user/queue/sourcing-acks`。公共状态帧只含匿名供方、价格、排名、版本和时间；本方价格/排名作为独立私有帧发给自身。每次发送、重连及服务器投递重新核验登录和权限，禁止订阅其他用户及任意主题。数据库事件账本保留待投递事件，断线后可从HTTP状态和幂等收据恢复。

完整风险模块尚在P7：本阶段提供带版本和证据编号的人工风险登记，未评估明确显示UNKNOWN而非默认无风险。定点提交、经理批准和发布均重新验证当前必填资质完整且有效。定点建议引用真实近12月绩效/报价或竞价结果及风险快照；采购经理通过Flowable批准/驳回/转办/重新提名，禁止本人审批。重新提名要发起新审批，审批期间依据变化拒绝回写并保留任务。无历史和HIGH/UNKNOWN风险必须显式确认例外/风险。发布后受邀方收到各自中标/落选结果；落选原因由配置决定披露，绝不返回对手身份或报价。
