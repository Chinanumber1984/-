仅保留四个启用的登录身份；两端账号分别认证，不能混用入口。

| 账号 | 身份 | 入口与职责 |
| --- | --- | --- |
| lijunhua | 内部测试人员 | `/?internal=1`，当前业务组织的供应商维护、寻源发布、测试与审批发起 |
| admin | 管理员 | `/?internal=1`，系统/流程管理及审批；平台管理权限 |
| lixiaolong | 供应商业务测试人员 | `/?portal=1`，已绑定供应商的报价与业务测试，不能管理联系人权限 |

两个门户身份都绑定到用户已发布寻源唯一邀请的供应商。它们能看到该供应商已收到的询价，不能借助参数查看其他供应商。发布RFQ只是向受邀供方发送通知，并不自动创建账号；供应商账号须先绑定联系人。

密码只保存在 `artifacts/SRM-local-review/runtime/登录账号.txt`。内部账号由原本机账号改名并保留原用户ID。初次配置后，已按用户要求统一本机测试密码；当前密码仅在上述私有账号文件中维护。原数据加密/HMAC/索引密钥、数据库凭证不变，不公开密码或密钥。

为了用两个内部身份测试原两级流程，测试职责合并：lijunhua 发起，admin 分别以SQE、采购经理职责处理两个节点。两级节点和“不得审核本人申请”规则不变。两个节点不要求由两名不同审批人执行的既有规则也未改变。

## 数据与会话处理

旧用户设置为 DISABLED，保留用户行、关联关系、业务记录和审批历史，不执行物理删除。原会话通过服务器的会话管理接口按用户退出，没有清空Redis、数据库或Docker卷。没有任务留给已停用的审批人。管理员的内置管理角色合并到 admin，旧 superAdmin/bizAdmin 等入口不再能登录。

配置前的数据库与账号文件完整备份在被Git忽略的 `.runtime/account-profile-backups/`。私有 `runtime/account-profile.json` 保存当前绑定及备份位置，不含密码。启动SQL不再插入旧账号；流程初始化优先使用 admin，兼容未升级实例的旧流程管理身份。重新执行启动脚本已验证只保留四个启用账号。

旧W10–15报告是当时的历史验收证据，其中的批量账号现已停用。当前入口和账号以本说明及 runtime 登录文件为准。旧批量脚本在当前实例被阻止或转入四账号验证，避免重新生成账号。

## 验证

`node scripts/test-four-account-review.mjs`：四个真实登录、两端角色和绑定、用户真实寻源的可见性、独立验收询价报价、组织/供应商隔离、原SQE/经理两级审批、本人申请禁止自审、旧会话失效及无已停用任务受理人。不会向用户原寻源提交测试报价；会新增带“四账号验收”前缀的测试询价、资质附件和供应商，记录保留。

`PLAYWRIGHT_BROWSERS_PATH=/tmp/srm-playwright /tmp/srm-browser-venv/bin/python3 scripts/test-four-account-browser.py`：四个账号通过真实登录表单进入正确工作台；两个门户身份均在门户首页看到用户已经发布的受邀询价，验证码策略保留。

结果见 `four-accounts-verification.json` 和 `four-accounts-browser.json`，均不包含密码。历史验收包的账号文件已私有归档，无须在多个管理员账号间切换。
