# W37 工作流分类映射维护测试用例

## 范围

验证 FR-FLOW-103：每个受控 SRM 业务类型恰好对应一个可维护分类；普通业务流程键保持稳定。仅在隔离验收副本执行会写入的步骤，不在主数据库试改分类。门户账号不得查看或维护该配置。

## 账号与准备

- 使用 `SYS-ADMIN` 或 `superAdmin` 内部管理员；另准备普通内部账号和供应商门户账号。
- 确认 V10 迁移已在隔离副本执行，初始应有 8 个映射：ONBOARD、CHANGE、FREEZE、UNFREEZE、ELIMINATE、AWARD、COL_REVIEW、QUALITY_REVIEW。
- 记录其中一个类型的当前分类编码、名称和行版本；推荐选用隔离副本的 `ONBOARD`。

## 用例

1. **映射清单与一一对应**：管理员打开“审批与生命周期 → 流程版本与分类”。确认 8 个业务类型各一行，每行可编辑分类编码和名称；无重复编码、无重复名称。当前流程列表按维护后的分类显示。
2. **管理员维护并即时反映**：将 `ONBOARD` 的编码和名称改为唯一值并保存。确认提示成功、该行行版本增加 1；流程定义列表中准入流程显示新分类。再次刷新页面，新值仍保留。
3. **保持流程类型和既有实例**：修改 `ONBOARD` 分类后，确认流程键仍为 `srm_onboard`；提交一条隔离准入流程并可按原审批链完成。若修改前有未完成实例，继续处理它并确认分类修改没有改变其业务类型、节点或办理状态。
4. **分类编码重复**：将 `CHANGE` 编码改成另一行正在使用的编码。确认服务拒绝保存并显示冲突；数据库行版本和其他映射不变。
5. **分类名称重复**：将 `CHANGE` 名称改为另一行名称。确认服务拒绝保存并显示冲突；映射不变。
6. **并发更新保护**：在两个管理员会话中读取相同行版本；先在会话 A 保存，再用会话 B 提交旧版本。确认 B 收到“已被其他管理员修改”冲突，A 的结果保留。
7. **权限边界**：普通内部用户尝试打开管理视图并直接 POST `/workflow/categories/ONBOARD`，确认写操作返回 403。门户直接 GET 与 POST `/workflow/categories` 路径均被拒绝，门户页面不出现映射管理入口。
8. **受控类型边界**：对 `/workflow/categories/OTHER` 提交更新，确认返回 400；不得新增任意流程类型或改变 `srm_*` 流程键。
9. **既有发布与上传路径**：管理员使用新类别映射发布受控流程版本、上传受控 BPMN 文件。确认发布/上传的流程定义类别采用当前映射编码，业务类型、白名单节点、候选角色验证保持原规则。

## 通过标准与限制

用例 1–9 均符合预期，重复操作不会造成映射重复或数据丢失。V10 是加法迁移：新增映射表并种入当前 8 类初始映射，不删除或改写业务表、流程实例、密钥或运行数据。外部工作流系统联调不在此用例范围。
