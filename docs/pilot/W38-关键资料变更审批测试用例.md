# W38 关键资料变更审批测试用例

## 范围

覆盖 PRD FR-CORE-104/501。只在隔离验收副本执行写入步骤。使用管理员账号；准备 `POTENTIAL`、`CORRECTION`、`QUALIFIED`、`FROZEN` 四种有效供应商档案各一份，并准备可处理采购经理审批的账号。

## 用例

1. **关键字段禁止直接保存**：对四种状态分别从档案编辑入口试改名称、品类、信用代码、银行账号或开户行。确认前端只提供“维护注册地址”，直接调用 `POST /suppliers/{id}/edit` 修改关键字段也返回冲突；原档案字段、行版本和审计历史不变。
2. **地址直接维护**：四种状态分别改注册地址并保存。确认保存成功，档案行版本增加，变更历史记录维护前后地址及操作人；其他关键字段保持原值。
3. **发起关键资料变更**：在四种状态分别打开“准入与审批 → 申请关键资料变更”，提交至少一个关键字段和原因。确认流程进入待审批，档案中的名称/品类/信用代码/银行资料仍显示原值，申请详情能够查看变更前值和拟变更值。
4. **审批通过后回写**：审批人批准其中一项变更。确认对应字段才更新；原状态保持不变、档案行版本递增；“变更记录”包含前后快照、审批人和时间，申请详情历史仍保留。
5. **审批驳回时保留原值**：另发起关键字段变更并驳回。确认档案关键字段、业务状态和有效资料未改变；审批历史显示驳回意见，不产生成功的资料版本。
6. **并发与流程隔离**：关键字段审批挂起时尝试直接保存地址或再次申请。确认活动申请阻止修改审批依据和重复申请；审批结束后地址维护恢复可用。门户联系人不能调用内部关键字段变更接口。

## 通过标准

所有关键字段变化只能通过 CHANGE 审批生效；批准后有前后版本证据，驳回后原值保留。地址仍可直接保存并审计。此阶段不涉及外部系统联调。
