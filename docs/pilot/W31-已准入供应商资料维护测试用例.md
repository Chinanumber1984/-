# W31 已准入供应商资料维护测试用例

## 范围

验证内部已准入档案的资料维护入口符合变更控制：注册地址可直接维护，名称、品类、信用代码、银行账号和开户行必须提交关键资料审批。测试在隔离副本操作，不修改主实例供应商档案。

## 前置条件

- 使用隔离副本，准备已准入且没有待办审批的供应商，以及有档案管理权限的内部账号。
- 记录档案版本、注册地址、名称、品类、信用代码和银行资料。
- 另准备 CAT-MGR 审批账号，并确认 `CHANGE` 流程已发布。

## 用例

1. **已准入档案入口清晰**：打开供应商详情，确认基础资料页显示“维护注册地址”和“申请关键资料变更”；进入地址维护弹窗，确认只出现注册地址字段，不出现可编辑的名称、品类、信用代码、银行账号或开户行字段。
2. **直接维护非关键字段**：修改注册地址并保存。确认详情显示新地址，档案版本增加，名称、品类、信用代码和银行资料不变，并生成可查的资料版本/审计记录。
3. **关键资料变更审批入口**：进入“申请关键资料变更”，提交新的银行账号或信用代码。审批未结束前确认原档案仍生效；待 CAT-MGR 批准后确认新值生效并保留版本历史。
4. **关键字段直改被服务端拒绝**：绕过界面调用编辑 API 修改已准入供应商名称或银行资料，确认返回冲突错误且数据库原值不变。
5. **版本冲突保护**：使用过期 `rowVersion` 保存注册地址，确认请求冲突且不会覆盖较新档案。
6. **不可维护状态**：淘汰供应商档案只读；存在进行中审批时地址维护被阻止，审批依据和状态不受影响。

## 验收记录

记录测试账号、隔离供应商编号、审批编号、结果及失败说明。本用例验证本地功能，不代表供应商业务负责人签收。
