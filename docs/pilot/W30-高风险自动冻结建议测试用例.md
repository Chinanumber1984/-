# W30 高风险自动冻结建议测试用例

## 范围

验证内部高风险评估自动创建原有 `FREEZE` 审批待办；审批仍由采购经理处理，只有审批通过才改变供应商状态。测试应在隔离副本执行，不要在正式测试供应商上提交冻结。

## 前置条件

- 使用隔离副本和 SQE、CAT-MGR 两类内部账号；确认流程管理员已发布 `srm_freeze` 流程。
- 创建一条隔离合格供应商及一条有明确证据引用的内部风险记录。
- 记录供应商状态、风险行版本和现有审批数量。

## 用例

1. **高风险自动建单**：SQE 将风险评为 HIGH。检查风险显示 `freezeSuggested=true` 且有 `freezeApprovalId`；该审批为 `FREEZE/PENDING`，经理待办可见；供应商仍为 `QUALIFIED`。
2. **审批权限与自审阻断**：评估人尝试处理自己的审批应被拒绝；有范围权限的 CAT-MGR 可看到并处理待办，其他组织用户不可见。
3. **同一风险重复评估不重复建单**：对同一风险再次保存 HIGH 评估，检查审批数量及 `freezeApprovalId` 不变，不重复提交流程。
4. **审批通过才冻结**：经理批准后，检查供应商为 `FROZEN`；核对风险仍保留评估、审批关联和操作历史。
5. **非高风险不建单**：将另一条隔离风险评为 MEDIUM 或 LOW，检查没有冻结审批待办且供应商状态不变。
6. **已有其他审批时的冲突处理**：供应商有未完成申请时尝试评为 HIGH；检查不会遗留重复或半创建的审批/风险记录，并确认界面可读到失败原因。
7. **门户隔离**：门户账号不能创建、查询或处理内部风险冻结审批。

## 验收记录

每项填写通过/失败、操作者、隔离供应商编号和审批编号。此用例记录本机功能验证，不代表业务负责人签收。
