# W33 供应商门户联系人角色权限矩阵测试用例

## 目标

确认门户不同联系人角色只看到与其职责相关的模块与操作；前端不发起无权限的查询，服务端仍独立执行授权。

## 自动化覆盖

运行 `node --test snowy-admin-web/src/workspace/portalCapabilities.test.mjs`，检查报价、发货、质量、财务、管理员、多角色组合，以及未知/空角色的权限矩阵。

## 手工验收步骤

准备绑定同一供应商的报价员、发货员、质量联系人、财务联系人，以及管理员账号。不要为验证而修改主实例角色或账单数据；如缺少角色账号，在隔离副本中创建。

| 角色 | 应显示 | 不应显示/请求 | 预期操作 |
| --- | --- | --- | --- |
| 报价员 `QUOTE` | 寻源、绩效 | 采购协同、质量、对账 | 可进入授权寻源/绩效页；不得读取协同通知或对账 |
| 发货员 `SHIP` | 采购协同、交付看板、物流相关订单、协同通知 | 对账与发票页签、工作台对账卡片及对账查询 | 可读取本供应商订单/物流与通知；无任何对账 API 403 请求 |
| 质量联系人 `QUALITY` | 质量与风险、绩效 | 寻源、采购协同、对账 | 可进入授权质量/绩效页；不得读取采购协同数据 |
| 财务联系人 `FINANCE` | 采购协同、对账与发票、绩效、协同通知 | 寻源、发货操作、质量 | 可查询本供应商对账并执行财务授权动作；不得执行物流操作 |
| 管理员 `ADMIN` | 全部门户业务模块 | 内部管理菜单 | 能看到全部门户模块，服务端数据仍限定到绑定供应商 |
| 多角色 | 对应角色权限的并集 | 未分配角色能力 | 如 `SHIP+FINANCE` 同时有物流和对账权限 |
| 未知/无角色 | 无业务模块 | 所有受限菜单和查询 | 服务端拒绝无授权调用 |

## 检查点

1. 逐个登录并确认侧栏和工作台卡片与表格一致。
2. 发货员进入采购协同，确认“对账与发票”页签和对账卡片均不出现；浏览器网络面板中不存在 `/collaboration/reconciliations` 请求。
3. 在隔离副本尝试以发货员直接调用对账读取、确认、差异、讨论和经理升级接口，均应被服务端拒绝；以财务联系人访问本供应商对账成功。
4. 尝试跨供应商读取时，仍应由既有服务端供应商范围校验拒绝。
5. 重载和退出重登后权限显示不变；未知角色默认无权限。

## 结果记录

- 自动化角色矩阵：`docs/review/W33-portal-role-verification.json`
- 主实例升级与只读冒烟：`docs/review/W33-main-deployment-verification.json`
- 实际角色账号/数据不足时，按上面的隔离副本步骤补充浏览器验收，不把管理员账号冒充其他角色的端到端验证。
