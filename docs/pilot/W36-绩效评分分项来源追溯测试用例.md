# W36 绩效评分分项与来源追溯测试用例

## 对应需求

FR-PER-104：评分明细展示分项，并可追溯至数据来源。此轮覆盖内部历史/沙箱输入记录；真实 ERP/MES/QMS 原始业务明细联调仍按计划延期。

## 前置条件

使用隔离数据库副本或既有专用合成绩效数据。准备一条已有评分，其来源输入行具备来源类型、来源凭据、分项分数、输入版本、导入批次和录入时间。不得在主实例写入测试评分。

## 用例

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| W36-01 | 内部账号打开“绩效管理”中的评分明细 | 展示交付、质量、成本、服务四项原始分、权重和加权贡献；总分及等级与列表一致。 |
| W36-02 | 查看“关联来源输入记录” | 输入记录ID、来源类型、来源凭据、输入版本、原始四项分数和记录时间与评分绑定的 SRM_PERF_INPUT 行一致；内部账号还可见导入批次及录入人。 |
| W36-03 | 展开历史评分版本 | 每个版本显示自身快照中的输入记录ID、输入版本、来源凭据、模板版本和分项；历史记录不随当前输入改变。 |
| W36-04 | 使用供应商门户账号打开本供应商评分明细 | 只显示本供应商的分项、来源凭据和输入记录版本；不返回或显示内部导入批次、录入人。 |
| W36-05 | 用其他供应商的门户身份请求该评分详情 | 服务端按现有 supplier_id 范围拒绝访问，不返回评分或来源证据。 |
| W36-06 | 查看历史导入、沙箱输入及申诉修正后的评分 | sourceType、sourceRef 和 inputId 指向实际生成该评分快照的输入行；不把沙箱/历史来源标成真实ERP/MES/QMS数据。 |

## 验证状态

SRM 绩效与质量插件完整 Maven 回归共 12 项通过，其中新增 3 项覆盖内部来源证据、门户敏感字段隐藏及跨供应商拒绝；Vite workspace 生产构建通过。尚未在 Windows 浏览器逐项执行，也不代表真实外部系统原始数据已接入。
