## 业务口径

- ERP为PO及其变更的权威源。通过认证、按来源+业务键+版本导入；重复幂等、乱序等待，失败可追查/重试。ERP主数据先映射已存在的SRM供应商，不自动绕过准入创建合格供应商。
- 新PO仅允许合格供应商。冻结/淘汰禁止新增或扩大采购承诺；既有PO允许确认、收发货、对账、发票与回执处理，防止无法履约/结算。
- 价格为同一订单币种的含税单价（4位），数量3位，按行四舍五入到2位后求和；不隐式换汇，不把未知运费混入行价。收货保存当时价格及订单版本，历史不静默重定价。
- 供应商SHIP/ADMIN确认当前版本交期/数量；异议仅生成ERP变更请求，原有效订单保留，ERP正式变更后重新确认。提交ASN需已确认PO，按物料行/批次记录，累计发运不得超过有效订单量。
- 收货可分批。默认容差±3%，按最终关闭的发运行累计实收与应收比较；部分收货不提前判短缺，超收即时提示。超差保留实收事实并预警，不偷偷改数量。
- 逾期未收完按服务端Asia/Shanghai日期提醒内部BUYER及本供方，风险事件只待评估，不直接冻结。P7接完整风险消费端；本阶段保留可追查事件。
- 对账按未占用的有效收货行生成，冻结价格/数量/金额快照，同一收货行不能重复进入活跃对账单。内部BUYER和门户FINANCE/ADMIN分别确认，同版本双方确认才生效；差异/争议清除旧确认并保留协商记录。争议可经真实Flowable升级CAT-MGR，不许申请人自审。
- 发票必有关联的双方确认对账单及私有附件，金额必须精确相等；不能用金额容差放过不匹配发票。内部FIN校验后通过durable outbox推共享；HTTP送达不是业务受理，更不是付款完成。可信签名回执才能更新受理/付款状态。
- 发票驳回允许带版本修订附件并保留历史，旧版本迟到回执不覆盖新状态。已受理发票不可任意改写；已结算收货不能直接冲销。

## 接口与安全

内部 `/srm/v1/collaboration`，门户 `/client/c/srm/v1/collaboration`。订单、发运、收货、对账、附件、发票及导出继承相同组织/SELF/供应商边界。门户身份始终来自会话，不接受请求指定本方supplier_id或org_id。未获独立字段权限不返回单价。

集成管理 `/srm/v1/integration` 仅SYS-ADMIN/superAdmin配置连接；业务用户只能触发其权限内的沙箱业务操作。外部入站 `/srm-integration/v1/ingress/{connectorId}` 使用HMAC-SHA256签名，绑定method、path、timestamp、nonce和body SHA256；5分钟时效，nonce防重放。事件业务幂等独立于传输nonce，重试需新nonce、原事件ID。组织、系统及SANDBOX/LIVE由服务器连接配置决定。

连接密钥SM4加密存库，监控不返回密钥/完整报文/明文单价。LIVE端点需HTTPS及服务端主机白名单；本机沙箱只能访问固定私有服务，不开放任意URL。财务附件经独立签名下载并验证所属组织/连接，不通过公开URL分享。

Inbox：持久接收、业务流版本锁、缺失版本等待、冲突留痕，成功和业务变更同事务。Outbox：持久租约、幂等事件ID、指数退避、有限重试与人工处理，远端已接受但响应丢失不重复入账。沙箱远端也持久去重账本，以实际HTTP/回调验证，不用进程内伪成功。
