## 已交付

| 能力 | 实际行为 |
| --- | --- |
| 注册 | 内部生成7天有效、单次使用的邀请码；组织由服务器邀请记录绑定。外部通过原生验证码与SM2密码注册独立门户账号，档案保持潜在。登录后补齐资质再提交准入。邀请码是本版外部注册归属组织的明确机制。 |
| 准入 | 潜在/补正→提交门槛→审核中→SQE→采购经理→合格，写入准入时间和初始等级。必须有品类要求的全部有效资质及有效管理员联系人。 |
| 补正与驳回 | SQE可退回补正；重提从SQE重新开始，补正次数默认3，达到上限默认淘汰，可配置。驳回恢复潜在，保留历史。经理可驳回，不能跳过SQE或直接设置状态。 |
| 关键资料变更 | 已准入供应商名称、品类、信用代码、银行资料不能通过普通编辑直接更换。变更申请和原值快照加密保存，审批通过前保留旧有效值，通过后写入可追溯版本。地址等非关键字段可直接编辑并审计。潜在/补正阶段允许维护尚未获批的草稿资料。 |
| 冻结/解冻/淘汰 | 经理发起，另一审批人处理；冻结前保持合格，解冻后恢复合格，淘汰为终态。当前提供新增业务准入阻断API，后续RFQ/PO/竞价入口必须接入后再次验收。 |
| 任务 | 组织、数据范围、角色和任务归属均在服务端验证；申请人与审批人分离。支持领取、同意、驳回、转办、加签及意见留痕。父任务在加签未完成时不能通过。 |
| 撤回 | 申请人或系统超管可撤回未结束申请；准入恢复提交前的潜在/补正状态，保留审计并解锁资料。 |
| 流程管理 | 流程管理员发布新版本、下载与上传受控BPMN、挂起/激活；已启动实例保留原版本，挂起阻止新发起。当前分类为准入、变更、冻结、解冻、淘汰。 |
| 待办与催办 | 真实工作台提供我的待办；原生Snowy首页新增待办卡片，并复用原生站内消息。默认48小时超时催办，同任务每日去重，接收人遵循角色与数据权限。 |
| 可靠回写与审计 | manager完成TaskListener同步调用业务回写，与Flowable共享数据库事务。失败时任务、意见、业务状态一并回滚。重复提交使用组织内幂等键及请求内容指纹；并发完成只能生效一次。 |
| 消息 | 事务内产生持久化outbox，企微/钉钉HTTPS适配器具备退避、5次失败入待处理和超管重试。未配置真实Webhook，不宣称外部送达通过。 |

## 亲自验收

1. 启动 `scripts/start-backend.sh` 和 `scripts/start-workspace.sh`。也可从原生Snowy首页待办卡片或SRM菜单进入；独立工作台使用相同真实后端。
2. 执行 `node scripts/prepare-workspace-access.mjs` 和 `node scripts/prepare-approval-access.mjs`。发起人与独立SQE/经理/流程管理员的登录信息分别保存在 `.runtime/workspace-access.md`、`.runtime/approval-access.md`，权限600且Git忽略；脚本不重置已有账号。
3. 流程管理员在“审批工作台”发布准入、变更、冻结、解冻、淘汰定义。每次发布产生新版本；已有开发测试定义可直接使用。
4. 发起人建档、建立管理员联系人、上传品类所需有效证书，在“准入与审批”提交。缺失资质应被阻止；提交后档案显示审核中。
5. SQE在“审批工作台”查看待办、核对供应商档案与资质，先退回补正。发起人查看意见、补充并重提。SQE通过后任务进入经理待办。
6. 使用独立经理账号同意。重新登录/刷新，供应商应显示合格、准入初始等级已写入。发起人不能审核自己的申请。
7. 申请银行等关键资料变更，检查待审期间仍显示旧值；经理通过后显示新值，版本追溯可查。
8. 分别申请冻结、解冻和淘汰，验证只有审批通过才改变状态，淘汰后无法再次发起准入。
9. 用其他组织、SELF范围和其他供应商门户尝试查看/处理申请；无权限的待办、详情和操作必须拒绝。
10. 在审批任务中验证领取、转办、加签，检查意见与签名历史；加签未完成时父节点不能通过。

## 回写失败如何恢复

集成测试在SQE通过后令必填证书失效，触发manager回写失败，确认任务保留、状态仍审核中、失败意见不落库；恢复测试夹具后并发重试，只有一次生效。此测试证明同库事务回滚与幂等，不是生产中直接修改数据库的操作指引。

真实使用中，若资质确已过期，应撤回申请，续期后重提；若属于临时数据库故障，修复故障后原任务可重试。进行中的审批锁定档案/证书，不能一边审批一边更换依据。关键资料变更在最终回写时再次校验信用代码唯一性，冲突会回滚。

## 配置与实现边界

- `srm.approval.correction-limit=3`、`srm.approval.eliminate-at-limit=true`；仅SQE退回计入补正次数，驳回或撤回不计。
- `srm.approval.initial-tier=QUALIFIED`；与后续绩效自动分级分开。
- `srm.approval.reminder-hours=48`，默认每小时扫描，业务日期Asia/Shanghai；任务每日催办去重。当前扫描/待办每批最多1000个申请，万级待办需补充分页与压测，不宣称已做规模验收。
- `SRM_MESSAGE_WEBHOOK_URL` 为可选运行时秘密，勿写入源码/截图/日志。仅允许企业微信/钉钉官方HTTPS目的地，禁止重定向；HTTP成功且业务errcode为0才确认。未配置时不消费outbox，不伪造发送成功；可通过超管消息监控API查看状态和重试失败项。
- Webhook为至少一次投递：远端已接收而本地超时仍可能重复通知，消息包含事件键便于排查。外部通道不得承担权威审批状态。
- BPMN上传只允许当前业务图与固定候选角色，可修改节点名称；拒绝外部实体、脚本、任意表达式和服务任务。此边界是受控流程发布，不是任意脚本流程平台。
- 定点/SCAR分类、绩效决策数据、风险自动建议冻结，以及后续RFQ/PO/竞价对状态门槛的实际调用，随相关领域阶段补齐；对应编号保持PARTIAL。
- 使用现有Snowy签名工具进行开发完整性验证。生产仍需受控签名密钥、密钥轮换、长期审计归档、备份恢复、时区部署约定、性能及等保等专项验收。

服务边界：core通过flow-api访问引擎；门户身份仍由Snowy C端登录与联系人实时绑定产生；流程候选组不替代组织、字段或任务授权。V5增加审批请求/加密快照、动作意见、资料版本、催办去重和注册邀请，不重建或清空旧表。
