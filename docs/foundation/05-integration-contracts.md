# 集成契约、网络与运行准备

## 统一事件信封（设计）

```json
{
  "eventId": "source-event-unique-id",
  "sourceSystem": "ERP",
  "businessKey": "PO:source-order-id",
  "sourceVersion": 3,
  "occurredAt": "2026-10-26T08:00:00Z",
  "sourceOrgCode": "factory-code",
  "payload": { "orderId": "source-order-id", "supplierCode": "source-supplier-code" }
}
```

sourceSystem由已认证的接入身份确定；sourceOrgCode必须经服务器维护的组织映射校验，不允许通过请求直接选择任意内部orgId。业务数据按最小必要字段传递；日志不记录完整敏感payload。

- 接收：签名/认证→来源与组织映射→事件去重(inbox)→版本顺序判断→业务事务提交→ACK。重复事件返回相同结果，旧版本不覆盖新版本。
- 发送：业务事务写outbox→提交→派发→保存回执。相同eventId重发保持幂等。
- 重试：指数退避并加抖动，区分可重试超时/5xx与不可重试校验错误；次数、最大延时和告警阈值可配置。超过上限进入人工处理，不静默丢弃。
- 对账：记录sourceId/businessKey/version/traceId与本地对象关系；提供按时间窗口校验数量、金额和回执。
- 安全：接口凭证只通过安全设置注入；本文件不包含地址猜测或凭证值。外部API应使用可校验TLS的HTTPS路由。

## 各系统所需资料

| 系统 | 需要对接方提供 | 首次联调通过标准 |
| --- | --- | --- |
| ERP | 厂商/版本、组织/供应商/物料编码字典、PO/价格/收货/付款报文、认证/回调和沙箱 | 同步一张多行PO，变更/重复/乱序处理正确 |
| MES | 物料/工厂映射、排产与领用接口、时间语义和沙箱 | 能追溯交付计算的排产来源 |
| QMS | 检验/PPAP/SCAR标识、质量口径、状态与回写协议 | 检验不合格关联供应商并形成可追溯事件 |
| 财务 | 对账/发票/申请/回执、金额税率和币种、幂等约定 | 推送与回执金额/状态一致，重试不重复 |
| 消息 | 企微或钉钉选型、测试应用、接收人映射与限流规则 | 指定审核人与供应商管理员可收到一条测试待办 |
| MinIO/KMS | 测试服务位置、最小授权账户元数据、桶策略、密钥版本管理方式 | 私有附件获授权下载、越权拒绝；密钥不进入日志/代码 |

当前没有上述真实沙箱资料；这里只完成契约和接入清单，没有声称完成联调。现有环境中Git/Maven/npm访问能力不代表ERP/QMS的访问授权。需要的具体域名在对接方提供地址后再增量加入网络配置，不能猜测后放开全网。

## 运行方案

研发使用现有Docker MySQL/Redis；迁移测试只操作独立srm_test_*数据库。应用密钥、业务库迁移与测试夹具独立管理。生产采用独立应用账户/迁移账户，备份加密、恢复演练、告警和归档。监控指标至少包括审批回写失败、outbox积压/重试、资质预警投递、数据库连接与接口失败率。

审计五年保留、RPO/RTO、接口SLA和性能指标以部署规格和明确统计窗口验收，基础设计阶段不作未经测试的达标声明。
